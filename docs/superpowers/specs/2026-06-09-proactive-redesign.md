# 推送系统 V2 设计文档

## 概述
重构主动推送系统，实现：安静时段、AI 自然文案生成、新增推送类型。

---

## 一、安静时段 + 晨间简报

### 1.1 安静时段规则
- **沉默窗口**: 每日 22:00 - 次日 8:00（北京时间）
- 定时循环 `_poll()` 检测到当前时间在窗口内 → 跳过所有用户检查
- 不记录任何 `proactive_pushes`

### 1.2 晨间简报
- **触发条件**: 用户在 8:00 后首次 WS 上线，且今日尚未推送过晨间简报
- **检查方式**: 查询 `proactive_pushes` 表，`push_type='morning_briefing'` AND `created_at >= 今日 0:00`
- **简报内容**:
  - ☀️ 今日天气摘要
  - 📅 今日日程列表
  - 💰 昨日消费总额 + 分类
  - 💧 一句暖心鼓励（LLM 生成）
- **发送**: 合并为一条"今日简报"推送，`push_type='morning_briefing'`

## 二、AI 自然文案生成

### 2.1 数据驱动 → 文案生成
**之前**: 每个 `_check_*()` 返回固定模板字符串，多个 HIT 用 `\n` 拼接。

**之后**:
1. 每个 `_check_*()` 返回 `dict | None`（结构化数据）
2. 所有 HIT 数据汇总为 lists
3. 调用 LLM 一次生成自然文案

### 2.2 检查数据格式
```python
_check_weather  → {"type": "weather", "city": "Dubai", "condition": "雨", "temp": 37}
_check_calendar → {"type": "calendar", "events": [{"title": "开会", "time": "14:00"}]}
_check_expense  → {"type": "expense", "yesterday_total": 200, "reminder": True}
_check_water    → {"type": "water", "hour": 14}
_check_idle     → {"type": "idle", "hours": 5}
_check_emotion  → {"type": "emotion", "current": "sad"}
_check_memory   → {"type": "memory", "topics": ["周杰伦", "旅行"]}
_check_news     → 不变（独立发送，不合并）
```

### 2.3 LLM 生成 Prompt
```
你是灵犀，一只关心主人的小猫。根据以下信息生成一条自然温暖的推送（不超过80字）：

当前时间: 14:30
用户所在: Dubai
数据: 天气=雨 37°C, 日历=14:00开会, 喝水提醒, 昨日消费¥200

要求: 自然流畅，不逐条复述，像小猫在跟主人说话。
```
- 每日最多 3 条推送 → 最多 3 次 LLM 调用
- 使用 `deepseek-v4-flash`，成本极低

## 三、新增推送类型

### 3.1 🎉 节日祝福
- **数据源**: 内置节日字典（春节/元宵/清明/端午/七夕/中秋/国庆/元旦/圣诞/除夕）
- **检查逻辑**: 混合推送日当天，若为节日 → 覆盖其他检查，单独推送节日祝福
- **文案**: LLM 根据节日名称 + 用户记忆生成
- **优先级**: 最高，跳过其他检查

### 3.2 📅 倒数日提醒
- **数据源**: 复用 `countdowns` 表
- **触发**: 倒数日到期前 3 天 / 当天 / 已过期 1 天
- **文案**: `"{title}" 还有 {n} 天！`

### 3.3 ⏰ 自定义提醒
- **新增表**: `reminder_schedules`
  - `user_id`, `content`（提醒内容）, `rule`（daily/weekly/...）, `time_of_day`（具体时间）, `active`
- **定时扫描**: 每 30 分钟检查到期提醒
- **用户设定**: 通过对话自然语言 → LLM 提取 → 存入表
- **文案**: 提醒内容原文

## 四、数据流

```
┌─ _poll() 每 3 小时 ──────────────────────────────┐
│                                                    │
│  1. 检查是否为安静时段 (22:00-8:00) → 跳过          │
│  2. 检查是否为节日 → 推送节日祝福                     │
│  3. 检查是否可推送 (_can_push DB 节流)               │
│  4. 运行 7 项检查，收集结构化数据                     │
│  5. 有数据 → LLM 生成自然文案 → 推送 + DB 记录       │
│  6. 倒数日检查 (独立)                                │
│  7. 新闻检查 (独立，不合并)                          │
│                                                    │
└────────────────────────────────────────────────────┘

┌─ WS 连接 ────────────────────────────────────────┐
│                                                    │
│  1. 检查是否 8:00 后首次上线 → 晨间简报              │
│                                                    │
└────────────────────────────────────────────────────┘

┌─ 每 30 分钟 ─────────────────────────────────────┐
│                                                    │
│  1. 扫描 reminder_schedules 到期提醒               │
│  2. 推送提醒                                        │
│                                                    │
└────────────────────────────────────────────────────┘
```
